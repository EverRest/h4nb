1. Il problema

Un ricercatore studia un disco o un ammasso attorno a un corpo massiccio: nubi di gas attorno a un nucleo galattico attivo (AGN), oppure stelle attorno a una massa centrale. Le particelle possono avere dal 10 % al 100 % della massa centrale, quindi il corpo centrale si muove.

  • Forze esatte: ogni particella attrae tutte le altre. Un calcolo completo delle forze con N = 1 024 000 sono circa 10¹² coppie.
  • Precisione controllata: l'errore relativo massimo dell'energia su un periodo orbitale medio è al massimo 1e-8. Lo deve dimostrare un'esecuzione misurata.
  • Velocità: le simulazioni grandi terminano in ore su GPU da data center.
  • Riproducibilità: stesso input, configurazione, dispositivi e build danno lo stesso output, bit per bit.

3. Architettura

Un solo header pubblico (include/h4nb/h4nb.hpp) e una sola classe, Simulation. Nessun tipo CUDA nell'API. I kernel GPU e l'oracolo CPU dei test condividono lo stesso header matematico (src/hermite.cuh).

Un passo a blocchi:

  1. Trovare il prossimo tempo di blocco Tn = min(next).
  2. Predire tutte le particelle a Tn.
  3. Selezionare le particelle attive (next == Tn).
  4. Inviare i target attivi a ogni GPU.
  5. Ogni GPU calcola a e jerk parziali delle proprie sorgenti su tutti i target (tile in shared memory, un thread per target).
  6. Inviare ogni porzione alla GPU proprietaria.
  7. Il proprietario somma i parziali nell'ordine dei dispositivi, corregge e sceglie il nuovo passo.

Memoria: circa 0,4 GB per GPU con 1M particelle. Il limite è il calcolo.

4. Avvio rapido

Build (Linux x86_64 o aarch64, CUDA ≥ 12.0, CMake ≥ 3.24, GPU con compute capability ≥ 7.0):

make build                                   # Release, CMAKE_CUDA_ARCHITECTURES=native
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=89      # RTX 4070 Ti
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=90      # GH200 / H100
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES="89;90" # both
cmake --build build -j

Esecuzione:

build/h4nb_mkdisk n=127999 frac=0.1 out=disk128k.snap     # prints mean / median / mass-weighted period
build/h4nb_run ic=disk128k.snap out=run128k t_end=6.3125 diag=0.0625 eta=0.0005 devices=0,1
build/h4nb_order e=0.5                                     # Kepler orbit + 4th-order check
build/h4nb_bench n=16384,131072,1024000 devices=0,1        # speed table
DT_MAX="0.015625 0.0078125" tools/eta_scan.sh disk128k.snap 6.3125 0.0625 0,1   # eta study

t_end, diag e snap devono essere multipli di dt_max (predefinito 1/64), e diag deve dividere t_end.

Come scegliere i valori principali

etaMisurarlo con lo studio di η. Partire da circa 0.0005. Il costo cresce come 1/√η.
dt_maxDa 1/64 a 1/16 del periodo più breve di interesse.
max_levelAumentarlo se compare l'avviso dt < dt_min.
eps0 per masse puntiformi; preset=agn o preset=stellar per i due tipi di modello.
diagUn controllo dell'energia costa N²/2 coppie. Con 1M usare T/16 o più.
tile, blocks_per_sm 🚧Misurarli con h4nb_bench; salvare i valori migliori nella config della macchina.
GPU / nodiLi imposta il launcher (devices=, mpirun, srun). La dimensione del cluster non è fissata nel codice.

6. Promemoria

File di configurazione 🚧

# configs/agn.cfg   (planned: T001, T011)
preset=agn                    # eps = 0.01
eta=0.0005                    # measured value for 1e-8
dt_max=0.015625
diag=0.0625

Esecuzione con file di configurazione 🚧

build/h4nb_run config=configs/agn.cfg ic=disk128k.snap out=run1 t_end=6.3125 devices=0,1
H4NB_ETA=0.00025 build/h4nb_run config=configs/agn.cfg ic=disk128k.snap out=run2 t_end=6.3125
build/h4nb_run config=run1/config.used out=run1_repeat     # repeat a run exactly

Più nodi 🚧

srun --ntasks-per-node=4 --gpus-per-task=1 --gpu-bind=single:1 \
  build/h4nb_run config=configs/gh200.cfg ic=disk1m.snap out=run1m t_end=6.3125
mpirun -np 8 --map-by ppr:4:node --bind-to core \
  build/h4nb_run config=configs/gh200.cfg ic=disk1m.snap out=run1m t_end=6.3125

C++ ✅

#include <cmath>
#include <h4nb/h4nb.hpp>

h4nb::Particles p = h4nb::read_snapshot("disk128k.snap");   // or h4nb::load_text("ic.txt")
h4nb::Config c;
c.eta = 5e-4;  c.dt_max = 1.0 / 64;  c.eps2 = 0.01 * 0.01;  c.devices = {0, 1};
h4nb::Simulation sim(p, c);
const auto e0 = sim.diagnostics();
sim.advance_to(6.3125);                                      // a multiple of dt_max
const auto e1 = sim.diagnostics();
double rel = std::abs((e1.E - e0.E) / e0.E);                 // the 1e-8 goal
if (sim.status() & h4nb::kNaN) { /* stop */ }

7. Problemi comuni

SintomoCausaAzione
max |dE/E| > 1e-8η troppo grandeRidurre eta (provare 0.0005, poi 0.00025). Eseguire lo studio di η.
warning: dt < dt_minUna particella richiede un passo più fineAumentare max_level. Controllare le coppie vicine.
warning: pair closer than r_closeIncontro ravvicinatoControllare r_min in timesteps.dat. Valutare il softening se il modello lo consente.
non-finite value (NaN or Inf)Input errato o collisioneControllare l'input. L'esecuzione si ferma per progetto.
advance_to: t must be a multiple of dt_maxt_end, diag o snap fuori grigliaUsare multipli di dt_max (1/64 = 0.015625).
La build fallisce con arch nativeNessuna GPU sulla macchina di buildImpostare CMAKE_CUDA_ARCHITECTURES=89 o 90.
Una chiave non ha effettoOggi le chiavi sconosciute sono ignorateControllare l'ortografia. 🚧 T005 la rende un errore.
Esecuzione 1M molto lenta su RTXFP64 lento (1/64)Usare RTX per N ≤ 131 072; GH200 per 1M.
Risultati diversi con numero di GPU diversoOrdine di somma diversoPrevisto. Confrontare con la tolleranza scritta, non bit per bit.
