1. The problem

A researcher studies a disk or a cluster around one heavy body: gas clouds around an active galactic nucleus (AGN), or stars around a central mass. The particles can have 10 % to 100 % of the central mass, so the central body moves.

  • Exact forces: every particle pulls on every other particle. One full force pass at N = 1 024 000 is about 10¹² pairs.
  • Controlled accuracy: the maximum relative energy error over one mean orbital period is 1e-8 or less. A measured run must show it.
  • Speed: large runs finish in hours on data-centre GPUs.
  • Reproducible: same input, configuration, devices and build give the same output bit for bit.

3. Architecture

One public header (include/h4nb/h4nb.hpp) and one class, Simulation. No CUDA type in the API. The GPU kernels and the CPU test oracle share one math header (src/hermite.cuh).

One block step:

  1. Find the next block time Tn = min(next).
  2. Predict all particles to Tn.
  3. Select the active particles (next == Tn).
  4. Send the active targets to every GPU.
  5. Each GPU computes the partial a and jerk of its own sources on all targets (shared-memory tiles, one thread per target).
  6. Send each slice to the owner GPU.
  7. The owner adds the partials in device order, corrects, and chooses the new step.

Memory: about 0.4 GB per GPU at 1M particles. Compute is the limit.

4. Quick start

Build (Linux x86_64 or aarch64, CUDA ≥ 12.0, CMake ≥ 3.24, GPU compute capability ≥ 7.0):

make build                                   # Release, CMAKE_CUDA_ARCHITECTURES=native
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=89      # RTX 4070 Ti
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=90      # GH200 / H100
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES="89;90" # both
cmake --build build -j

Run:

build/h4nb_mkdisk n=127999 frac=0.1 out=disk128k.snap     # prints mean / median / mass-weighted period
build/h4nb_run ic=disk128k.snap out=run128k t_end=6.3125 diag=0.0625 eta=0.0005 devices=0,1
build/h4nb_order e=0.5                                     # Kepler orbit + 4th-order check
build/h4nb_bench n=16384,131072,1024000 devices=0,1        # speed table
DT_MAX="0.015625 0.0078125" tools/eta_scan.sh disk128k.snap 6.3125 0.0625 0,1   # eta study

t_end, diag and snap must be multiples of dt_max (default 1/64), and diag must divide t_end.

How to choose the main values

etaMeasure it with the η study. Start near 0.0005. Cost grows as 1/√η.
dt_max1/64 to 1/16 of the shortest period of interest.
max_levelRaise it if you see the warning dt < dt_min.
eps0 for point masses; preset=agn or preset=stellar for the two model types.
diagOne energy check costs N²/2 pairs. At 1M use T/16 or more.
tile, blocks_per_sm 🚧Measure with h4nb_bench; keep the best values in the machine config.
GPUs / nodesSet by the launcher (devices=, mpirun, srun). The cluster size is not fixed in the code.

6. Cheat sheet

Config file ✅

# configs/agn.cfg
preset=agn                    # eps = 0.01
eta=0.0005                    # measured value for 1e-8
dt_max=0.015625
diag=0.0625
period=6.283185307179586      # 2*pi for G = 1, M = 1, a = 1

Run with a config file ✅

build/h4nb_run config=configs/agn.cfg ic=disk128k.snap out=run1 t_end=6.3125 devices=0,1
H4NB_ETA=0.00025 build/h4nb_run config=configs/agn.cfg ic=disk128k.snap out=run2 t_end=6.3125
build/h4nb_run config=run1/config.used out=run1_repeat     # repeat a run exactly

Several nodes 🚧

srun --ntasks-per-node=4 --gpus-per-task=1 --gpu-bind=single:1 \
  build/h4nb_run config=configs/gh200.cfg ic=disk1m.snap out=run1m t_end=6.3125
mpirun -np 8 --map-by ppr:4:node --bind-to core \
  build/h4nb_run config=configs/gh200.cfg ic=disk1m.snap out=run1m t_end=6.3125

C++ ✅

#include <cmath>
#include <h4nb/h4nb.hpp>

h4nb::Particles p = h4nb::read_snapshot("disk128k.snap");   // or h4nb::load_text("ic.txt")
h4nb::Config c;
c.eta = 5e-4;  c.dt_max = 1.0 / 64;  c.eps2 = 0.01 * 0.01;  c.devices = {0, 1};
h4nb::Simulation sim(p, c);
const auto e0 = sim.diagnostics();
sim.advance_to(6.3125);                                      // a multiple of dt_max
const auto e1 = sim.diagnostics();
double rel = std::abs((e1.E - e0.E) / e0.E);                 // the 1e-8 goal
if (sim.status() & h4nb::kNaN) { /* stop */ }

7. Common problems

SymptomCauseAction
max |dE/E| > 1e-8η too largeLower eta (try 0.0005, then 0.00025). Run the η study.
warning: dt < dt_minA particle needs a finer stepRaise max_level. Check close pairs.
warning: pair closer than r_closeClose encounterCheck r_min in timesteps.dat. Consider softening if the model allows it.
non-finite value (NaN or Inf)Bad input or a collisionCheck the input. The run stops by design.
advance_to: t must be a multiple of dt_maxt_end, diag or snap not on the gridUse multiples of dt_max (1/64 = 0.015625).
Build fails with arch nativeNo GPU on the build machineSet CMAKE_CUDA_ARCHITECTURES=89 or 90.
Exit code 2 and a key=value messageUnknown key, bad value or value out of rangeRead the message: it names the key, the value and the source. Run help=1.
1M run is very slow on RTXLow FP64 rate (1/64)Use RTX for N ≤ 131 072; use GH200 for 1M.
Results differ between GPU countsDifferent sum orderExpected. Compare with the written tolerance, not bit for bit.
