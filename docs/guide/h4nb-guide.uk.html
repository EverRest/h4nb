1. Проблема

Дослідник вивчає диск або скупчення навколо одного масивного тіла: хмари газу навколо активного ядра галактики (АЯГ) або зорі навколо центральної маси. Сумарна маса частинок може становити від 10 % до 100 % центральної маси, тому центральне тіло рухається.

  • Точні сили: кожна частинка притягує всі інші. Один повний розрахунок сил для N = 1 024 000 — це приблизно 10¹² пар.
  • Контрольована точність: максимальна відносна похибка енергії за один середній орбітальний період не перевищує 1e-8. Це має показати виміряний запуск.
  • Швидкість: великі запуски тривають години на серверних GPU.
  • Відтворюваність: ті самі вхідні дані, конфігурація, пристрої та збірка дають побітово той самий результат.

3. Архітектура

Один публічний заголовок (include/h4nb/h4nb.hpp) і один клас, Simulation. В API немає CUDA-типів. GPU-ядра та CPU-оракул тестів використовують один математичний заголовок (src/hermite.cuh).

Один блоковий крок:

  1. Знайти наступний час блоку Tn = min(next).
  2. Спрогнозувати всі частинки до Tn.
  3. Вибрати активні частинки (next == Tn).
  4. Надіслати активні цілі на кожну GPU.
  5. Кожна GPU обчислює часткові a та jerk своїх джерел для всіх цілей (тайли в shared memory, один потік на ціль).
  6. Надіслати кожну частину GPU-власнику.
  7. Власник додає часткові суми в порядку пристроїв, коригує і вибирає новий крок.

Пам'ять: приблизно 0,4 ГБ на GPU для 1M частинок. Обмеження — обчислення.

4. Швидкий старт

Збірка (Linux x86_64 або aarch64, CUDA ≥ 12.0, CMake ≥ 3.24, GPU з compute capability ≥ 7.0):

make build                                   # Release, CMAKE_CUDA_ARCHITECTURES=native
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=89      # RTX 4070 Ti
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES=90      # GH200 / H100
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CUDA_ARCHITECTURES="89;90" # both
cmake --build build -j

Запуск:

build/h4nb_mkdisk n=127999 frac=0.1 out=disk128k.snap     # prints mean / median / mass-weighted period
build/h4nb_run ic=disk128k.snap out=run128k t_end=6.3125 diag=0.0625 eta=0.0005 devices=0,1
build/h4nb_order e=0.5                                     # Kepler orbit + 4th-order check
build/h4nb_bench n=16384,131072,1024000 devices=0,1        # speed table
DT_MAX="0.015625 0.0078125" tools/eta_scan.sh disk128k.snap 6.3125 0.0625 0,1   # eta study

t_end, diag і snap мають бути кратними dt_max (за замовчуванням 1/64), а t_end має ділитися на diag.

🚧 Заплановано (T004–T013): одна таблиця ключів, п'ять джерел. Пізніше джерело перемагає:

  1. значення за замовчуванням
  2. preset=none|agn|stellar
  3. config=<file> (рядки key=value)
  4. змінні середовища H4NB_<KEY>
  5. командний рядок

Невідомий ключ або хибне значення — це помилка (код виходу 2). Кожен запуск записує config.used. help=1 друкує всі ключі.

Як вибрати основні значення

etaВиміряйте через дослідження η. Почніть з ≈0.0005. Вартість росте як 1/√η.
dt_maxВід 1/64 до 1/16 найкоротшого періоду, що вас цікавить.
max_levelЗбільште, якщо бачите попередження dt < dt_min.
eps0 для точкових мас; preset=agn або preset=stellar для двох типів моделей.
diagОдна перевірка енергії коштує N²/2 пар. Для 1M беріть T/16 або більше.
tile, blocks_per_sm 🚧Виміряйте через h4nb_bench; збережіть найкращі значення в конфігу машини.
GPU / вузлиЗадає лаунчер (devices=, mpirun, srun). Розмір кластера в коді не зафіксовано.

6. Шпаргалка

Файл конфігурації 🚧

# configs/agn.cfg   (planned: T001, T011)
preset=agn                    # eps = 0.01
eta=0.0005                    # measured value for 1e-8
dt_max=0.015625
diag=0.0625
period=6.283185307179586      # 2*pi for G = 1, M = 1, a = 1

Запуск з файлом конфігурації 🚧

build/h4nb_run config=configs/agn.cfg ic=disk128k.snap out=run1 t_end=6.3125 devices=0,1
H4NB_ETA=0.00025 build/h4nb_run config=configs/agn.cfg ic=disk128k.snap out=run2 t_end=6.3125
build/h4nb_run config=run1/config.used out=run1_repeat     # repeat a run exactly

Кілька вузлів 🚧

srun --ntasks-per-node=4 --gpus-per-task=1 --gpu-bind=single:1 \
  build/h4nb_run config=configs/gh200.cfg ic=disk1m.snap out=run1m t_end=6.3125
mpirun -np 8 --map-by ppr:4:node --bind-to core \
  build/h4nb_run config=configs/gh200.cfg ic=disk1m.snap out=run1m t_end=6.3125

C++ ✅

#include <cmath>
#include <h4nb/h4nb.hpp>

h4nb::Particles p = h4nb::read_snapshot("disk128k.snap");   // or h4nb::load_text("ic.txt")
h4nb::Config c;
c.eta = 5e-4;  c.dt_max = 1.0 / 64;  c.eps2 = 0.01 * 0.01;  c.devices = {0, 1};
h4nb::Simulation sim(p, c);
const auto e0 = sim.diagnostics();
sim.advance_to(6.3125);                                      // a multiple of dt_max
const auto e1 = sim.diagnostics();
double rel = std::abs((e1.E - e0.E) / e0.E);                 // the 1e-8 goal
if (sim.status() & h4nb::kNaN) { /* stop */ }

7. Типові проблеми

СимптомПричинаДія
max |dE/E| > 1e-8η завеликеЗменште eta (спробуйте 0.0005, потім 0.00025). Запустіть дослідження η.
warning: dt < dt_minЧастинці потрібен дрібніший крокЗбільште max_level. Перевірте близькі пари.

advance_to: t must be a multiple of dt_maxt_end, diag або snap не на сітціВикористовуйте кратні dt_max (1/64 = 0.015625).
Збірка падає з arch nativeНа машині збірки немає GPUЗадайте CMAKE_CUDA_ARCHITECTURES=89 або 90.
